# A‑07. Резерв страниц MemStack на первый полный кадр Weight

При повторном переходе Stairs → Weight резерв до 128 страниц сократил p95 самого длинного кадра с 24,918 до 22,590 мс (−9,3%). Первый полный кадр ускорился во всех трёх парах запусков. Бюджет перехода 16,67 мс всё ещё превышен. Резерв остаётся опцией диагностического пакета. Перед включением в обычной сборке нужно повторить сравнение на минимальной конфигурации с 8 ГБ ОЗУ, включая выход и запрос на освобождение памяти.

## Проверка освобождения

- В двух входах в Weight запрос на очистку памяти в начале первого полного кадра закрыл резерв досрочно. Из 128 страниц уже были выданы 14 и 8, оставшиеся 114 и 120 вернулись в кучу. Это проверка обработчика UE. Реальную нехватку памяти в Windows не воспроизводили.
- В упакованной игре с обычным запуском и с лимитом 128 прошли `EntryCourse`, `EntryCheckpoint`, `WorldLifetime`, `VulkanExitControl` и `VulkanTravelControl`. Все десять запусков завершились с кодом 0.
- Ещё в двух запусках с лимитом 128 команда выхода была задана при старте в Weight и сразу после команды перехода в Weight. В обоих журналах резерв успел закрыться в конце кадра: выданы все 14 и 117 принятых страниц соответственно. Игра штатно завершилась. Отдельного срабатывания обработчика выхода при ещё открытом резерве здесь не наблюдалось.
- Пакет собран и упакован из обновлённого исполняемого файла с ранее приготовленным контентом. Пройдена проверка архитектуры. Анализаторы воспроизводят прежние сводки без нового параметра и отклоняют записи с превышением лимита, нарушением баланса, отсутствующей или сдвинутой меткой кадра и неверной причиной закрытия.

## Что проверялось

Один Win64 Development пакет UE 5.7.4, Vulkan SM6, Binned2. Разрешение 1920 × 1080, масштаб 100%, тени 2, без VSync и ограничения FPS. Windows 11 x64 26300.10066, Core i5‑14400F, RTX 4070 Ti SUPER, драйвер 621.24, 32 ГБ ОЗУ. SHA‑256 игрового exe `f2d8fbac7a95263e5dda5c3a271da13f84e5b9f72eae4966fb95719a788c6761`. Подсчёт запросов опирается на [метки MemStack из #63](A07MapPages.md). Предельный размер резерва — 128 страниц по 64 КиБ, суммарно 8 МиБ.

Оба режима проходят обычную выгрузку Stairs и полный GC. В A лимит равен 0. В B только при открытии `/Engine/Maps/Entry?Chamber=Weight` до 128 страниц, которые пул уже попытался вернуть в кучу при очистке, временно помещаются в резерв. Память заранее не выделяется. Потоки сначала используют обычный пул. Когда он пуст, запрос страницы MemStack может получить сохранённый блок с подходящим выравниванием. Объём ограничен на весь вход, даже если ранняя очистка вызывается дважды.

После успешного выхода из `LoadMap` резерв живёт до `OnEndFrame`, которому предшествовал следующий `OnBeginFrame`. Неиспользованная часть возвращается в кучу, выданные страницы продолжают обычный жизненный цикл. Путь досрочного закрытия предусмотрен для другой карты, ошибки загрузки, запроса на очистку памяти и завершения движка. В эксперименте срок привязан к полному тику игрового потока. Завершение работ GPU отдельно не синхронизируется.

## Как сравнивали

Шесть независимых процессов в порядке A1, B1, B2, A2, B3, A3. Каждый начинал с новым профилем и 12 раз входил в Weight, возвращаясь в Stairs. Первые посещения сохранены в CSV. По остальным 33 наблюдениям каждого режима посчитаны медиана, p95 (32-е значение упорядоченного ряда) и максимум. При сравнении времени подробная трассировка отдельных запросов страниц была выключена. [Каждый переход](Measurements/A07-MapReserveTiming.csv)

Кадр перехода — максимум 12 кадров начиная с команды открытия. Время первого полного кадра берётся из CSV по событию `MapPageFirstFullEnd`. В отдельной CPU-трассе проверяется, что обработчик закрытия находится именно внутри первого полного `FEngineLoop::Tick` после возврата из `LoadMap`. Для каждого посещения отдельно вычисляются максимум следующих 11 кадров, p95 и максимум следующих 120 кадров. Кадр закрытия исключён из этих последующих окон.

Рабочий набор — пиковый счётчик процесса Windows. Private bytes и выделенная VRAM по WDDM — максимальные показания процесса при опросе с ожиданием 100 мс. Пики относятся ко всему запуску; срок жизни резерва короче интервала опроса. Сколько страниц реально удерживалось и было выдано, показывает баланс каждого посещения. [Память, число выборок и идентификаторы запусков](Measurements/A07-MapReserveRuns.csv)

## Повторение

К исходному движку пакета примените [патч подсчёта страниц](../Scripts/EnginePatches/UE-5.7.4-MapPageExperiment.patch), затем [дополнение для ограниченного резерва](../Scripts/EnginePatches/UE-5.7.4-MapPageReserve.patch) командой `git apply`. Пересоберите Win64 Development пакет. Опыт включается параметром запуска. Для независимых измерений нужны оба варианта в одном исполняемом файле.

```powershell
foreach ($limit in 0, 128, 128, 0, 128, 0) {
    ./Scripts/Measure-VulkanPackage.ps1 -PackageRoot $package -WeightVisits 12 -TraceTravel -MapPageReserve $limit
}
foreach ($limit in 0, 128) {
    ./Scripts/Measure-VulkanPackage.ps1 -PackageRoot $package -WeightVisits 5 -TraceTravel -TraceMapPages -MapPageReserve $limit
}
./Scripts/Measure-VulkanPackage.ps1 -PackageRoot $package -WeightVisits 2 -TraceTravel -TraceMapPages -MapPageReserve 128 -TestMapReserveTrim
./Scripts/Invoke-UeVerification.ps1 -PackageRoot $package -MapPageReserve 128 -Scenario EntryCourse,EntryCheckpoint,WorldLifetime,VulkanExitControl,VulkanTravelControl
```

Экспортируйте из Timing Insights события всех CPU-потоков с колонками `ThreadName,TimerName,StartTime,EndTime,Depth`. Маска `MemStack_*` в [списке таймеров](A07MapPages.md#повторение) включает метку закрытия. Сохраните все переходы и 12 полных тиков после каждого.

```powershell
python Scripts/Summarize-MapPages.py $run C:/Captures/Pages.csv
python Scripts/Summarize-VulkanProfile.py $run
```
