# A‑01. Локальная сборка доверенной ревизии

Запускатель получает исходники напрямую из публичного `hhypest/abandoned`. По умолчанию он выбирает вершину `main`. Параметр `-Commit` принимает полный SHA из истории первых родителей `origin/main`. Так можно повторить конкретную принятую сборку после очередного слияния. Ссылки на ветки, произвольные SHA из PR и код текущей рабочей копии в сборку не попадают. Сам запускатель берите из проверенной ревизии.

## Подготовка Windows x64

- Установите PowerShell 7, Git for Windows с Git LFS, Visual Studio 2022 с рабочей нагрузкой MSVC x64 и Windows SDK. [Зафиксированные версии](../Scripts/TrustedBuild/Toolchain.psd1)
- Подготовьте доверенную исходную установку UE на Epic `260bb2e1c5610b31c63a36206eedd289409c5f11`. Примените из `Scripts/EnginePatches` четыре поправки UE 5.7.4 — `PartialDepth`, `ListenerUpdates`, `SmallFullGC` и `LoadMapScopes`. Используйте отдельный подготовленный экземпляр движка с собранными редактором Win64 Development, UBT и зависимостями. Учётные данные Epic нужны при подготовке движка. Для получения публичной копии игры хватает анонимного HTTPS. [Подготовка движка](../CONTRIBUTING.md)
- Укажите короткий доступный для записи путь для запусков. Каждая попытка создаёт в нём новый каталог. Для переносимости настройки UBT из общих каталогов движка, ProgramData и Documents должны быть пустыми либо отсутствовать.

Для подготовки общих модулей один раз соберите редактор из этой копии UE, подставив путь к доверенной копии игры. UBT и UnrealHeaderTool должны быть собраны этой же установкой. Следующие прогоны будут компилировать модули игры из новых клонов.

```powershell
& 'C:\UE\5.7.4\Engine\Build\BatchFiles\Build.bat' AbandonedEditor Win64 Development '-Project=C:\src\abandoned\Abandoned.uproject' -WaitMutex
```

## Проверка на чистой main

21 ноября 2026 г. два независимых клона `5daf01e52364101380a3395a86d16ed6a4ead01e` материализовали 21 объект LFS, прошли обе конфигурации автономных тестов и собрали `AbandonedEditor Win64 Development`. UBT завершился с кодом 0 за 23,24 и 31,31 с соответственно. Это время UBT, без клонирования и тестов. В первом из приведённых в отчёте клонов сценарий `EntryCourse` прошёл до пополнения кислорода на станции. Процесс редактора завершился с кодом 0 на Vulkan SM6, RTX 4070 Ti SUPER, 1280 × 720.

Повтор подтверждает сборку одной ревизии и одинаковый состав выходных файлов. SHA‑256 receipt редактора и манифеста модулей совпали. Хеши DLL различаются. В двух DLL есть пути разных рабочих каталогов и разные отметки времени PE. Побайтовая воспроизводимость модуля в этой конфигурации не достигнута.

В отдельной попытке запускатель отклонил существующий SHA ветки PR #78 (`66fc4d9`) до checkout проекта, загрузки LFS и вызова UBT. Это второй родитель коммита слияния. [Отчёты обоих запусков, хеши, результат Vulkan и отрицательный контроль](Measurements/A01-TrustedEditor.json)

## Запуск

```powershell
./Scripts/Invoke-TrustedUnrealBuild.ps1 -EngineRoot C:\UE\5.7.4 -RunsRoot C:\UEBuilds
```

Для повтора допишите `-Commit` и полный SHA из `report.json`. Запускатель сохраняет каталог и при ошибке. Ненулевой код процесса означает провал. Для запуска из CI используйте `pwsh -NoProfile -File Scripts/Invoke-TrustedUnrealBuild.ps1` с теми же аргументами.

1. Новый процесс получает минимальное окружение Windows, пути к Git и PowerShell и собственные каталоги профиля, AppData, TEMP, NuGet и .NET CLI. Он клонирует `main`, проверяет SHA до переключения на ревизию, материализует Git LFS и сверяет содержимое с указателями.
2. Проверяются версия и базовая ревизия исходников UE, набор и содержимое четырёх изменённых файлов, версия встроенного .NET, фактические MSVC и SDK. На подготовленном движке UBT собирает проект с запретом пересборки общих продуктов движка. Распределённые исполнители и UBA отключены.
3. Выполняются автономные C++20-тесты с `NDEBUG` и без него, включая отрицательные контроли. После этого строится `AbandonedEditor Win64 Development`. Проверяются receipt, манифест модулей, DLL модуля и чистота исходников.
4. В каталоге запуска остаются `report.json` с SHA, версиями, результатом и хешами продуктов, `build.log` и подробный `UBT.log`. При ошибке UBT отчёт сохраняет его код завершения. Для функциональной проверки собранного модуля используйте `Project/Scripts/Invoke-UeVerification.ps1` **из полученной копии** с параметрами `-EngineRoot`, `-Scenario EntryCourse` и `-Resolution 1280x720`.

Изоляция проверена на уровне проекта и процесса. У запусков разные копии Git, `Binaries`, `Intermediate`, временные файлы и пользовательские настройки инструментов. Общими остаются учётная запись Windows, права пользователя, сеть, реестр, подготовленный UE и установленный компилятор. Этот режим предназначен для уже принятых ревизий. Публичный PR проверяется на GitHub-hosted Windows runner, где отдельно выполняется отрицательный контроль допуска SHA. Дальнейший этап A‑01 — независимый UE-runner и обязательный статус UE-сборки в политике слияния.
