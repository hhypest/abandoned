# A‑07. Финальная приёмка штатного режима

Упакованная игра Win64 Development UE 5.7.4, Windows 11, i5‑14400F, RTX 4070 Ti SUPER, 32 ГБ, Vulkan SM6, 1920 × 1080. Сборка из измерений #76, SHA‑256 EXE `4b029298768b6568f28ecba515d2147fd0fc0fe64cd4e8a082f6c0cf3184a493`. Штатная геометрия использует раздельную коллизию и инстансинг декора. Для замера дисплея игра сама выставляет VSync и лимит 60 кадров/с в свежем профиле. Измеритель проверяет фактические значения. В прежней серии ограничитель снимался. Тайминги двух профилей напрямую не сопоставляются.

## Ранний выход и повторный запрос

В отдельном диагностическом маршруте удерживали завершение асинхронной операции штатной переменной UE `s.StreamableDelegateDelayFrames=280`. Это воспроизводит окно между запросом и уведомлением, в том числе когда накопитель успевает закончить чтение. Маршрут переходит из Stairs в пустой мир на кадре 90, выполняет обычный GC, возвращается в Stairs на кадре 235 и открывает Weight на кадре 640. Для воспроизводимости событий здесь использован фиксированный шаг симуляции. Этот маршрут исключён из статистики производительности.

| Сценарий | Наблюдение в пакете |
| --- | --- |
| Штатный путь | Выход в пустой мир и повторный вход прошли. При возвращении в Weight появились четыре куба. Экспериментальная загрузка оболочки в этом режиме выключена. |
| Предзагрузка включена | Первый запрос — кадр 29. После выхода и возврата второй запрос — 265. Единственное уведомление готовности пришло на 545, через 280 кадров после второго запроса. В окне, когда должно было прийти первое уведомление, его нет. Затем успешно создан Weight. |
| Завершение приложения с ожидающим уведомлением | Запрос на кадре 29. Профилирование завершилось на 90-м, приложение штатно вышло до доставки уведомления. |

Все три процесса завершились с кодом 0 и штатным выходом Vulkan. Проверены временные окна, отсутствие лишних уведомлений, маршрут и сообщения об утечках. В текущей реализации callback держит слабую ссылку на библиотеку и ставит только метку готовности. Результат относится к отмене прикладного запроса; физическое прерывание чтения накопителем здесь не измерялось. [Проверка в пакете](../Scripts/Test-WeightLoadRetry.ps1)

## Холодный запуск и повторные входы

Первым после обычной перезагрузки Windows запускается C, за ним три новых процесса W1–W3. В каждом — первый вход в Weight и 15 повторных переходов Stairs → Weight. Отдельно сохраняются длительность запуска процесса до завершения инициализации движка, кадры после старта CSV, p95/p99 времени кадра, CPU/GPU и 60 тёплых переходов. Используется тот же EXE со штатным кешированием Windows и драйвера. Первый запуск обязан иметь более позднюю метку загрузки ОС, чем запись подготовки. Один холодный запуск даёт одно наблюдение длительности старта.

До перезагрузки отдельно проверен измеритель на коротком маршруте. Журнал подтвердил VSync=1 и t.MaxFPS=60. Эти кадры исключены из холодной серии. Проверка минимальных 8 ГБ ОЗУ остаётся задачей беты.
