# A‑07. Повторная загрузка моделей ФосТех при входе в Weight

На переходе Stairs → Weight сборка мусора удаляла объекты ресурсов ушедшей камеры. При инициализации новой камеры четыре вызова `LoadObject<UStaticMesh>` снова обращались к игровым пакетам. В новой версии `UChamberMeshLibrary` держит общие меши в пределах экземпляра игры, пока очередная карта использует библиотеку. Ссылка на мир слабая. При загрузке мира без этих моделей библиотека освобождает ссылки.

## Упакованная игра на Vulkan

Windows 11 x64, i5-14400F, RTX 4070 Ti SUPER, 32 ГБ ОЗУ, драйвер NVIDIA 621.24. Пакет UE 5.7.4 Win64 Development, Vulkan SM6, Binned2, 1920 × 1080, масштаб 100%. Для измерений отключены VSync и ограничитель частоты кадров. В обычной игре значения по умолчанию — VSync включён, 60 к/с. Диагностический резерв MemStack отключён в обеих сериях. SHA-256 EXE 196a059f990f2246a2b16d405f02f45829ba60fbed417e019d02b80a5822d189, SHA-256 Abandoned-Windows.ucas c95118f30a0b4cfc0896a2cfbf30c68214444eb191d8da2f452e12ae2f0a4b91.

Один исполняемый файл, шесть независимых процессов в порядке A1, B1, B2, A2, B3, A3. В A задан `-NoChamberMeshReuse`, в B действует обычная политика. Первичная загрузка самой Stairs по журналу LoadMap заняла 99,371–107,786 мс в A и 99,622–112,836 мс в B.

## Загрузка отдельных пакетов

В отдельном диагностическом прогоне с `LogStreaming VeryVerbose` в кадре повторного входа со старым поведением зарегистрированы 16 завершений загрузки пакетов ФосТех. Это четыре меша из таблицы, три материала (`M_Retro`, `M_Speaker`, `M_Panel`) и по три текстуры (`BC`, `MR`, `N`) для каждого материала. Подробный журнал снимался отдельно от серии A/B. Области CPU-трассы охватывают вызовы LoadObject для каждого меша вместе с его зависимостями. Основание и верх плиты используют общий материал. Эти интервалы включены во время Training_InitGame.

В отдельном прогоне маршрут Weight → пустой мир → Weight дал для каждого из четырёх мешей последовательность 1 → 0 → 1 по команде `obj list class=StaticMesh name=…`. В пустом мире перед подсчётом выполнена `obj gc`.

В этом пакете прошли EntryCourseAlternate, EntryCheckpoint, WorldLifetime, VulkanExitControl и VulkanTravelControl. В окне Weight проверены обе кнопки меню. При выключении VSync драйвер перешёл с MAILBOX на IMMEDIATE. На новом профиле подтверждены 60 к/с и включённый VSync, после выбора 120 к/с и выключения VSync оба значения восстановились при перезапуске. Проверены все четыре лимита. Профиль с прежним лимитом 0 получил 60 к/с с сохранением ранее выбранного VSync.

Для воспроизведения нужны собранный Development-пакет и Windows с Vulkan. Откройте Travel.utrace в Unreal Insights. На игровом потоке раскройте Training_InitGame для каждого второго открытия карты, начиная с первого входа в Weight. Имена четырёх дочерних интервалов совпадают с полными путями мешей. Скрипт сохраняет CSV кадров, журнал, снимки памяти и описание запуска рядом с трассой.

```powershell
./Scripts/Measure-VulkanPackage.ps1 -PackageRoot $package -TraceTravel -WeightVisits 8 -DisableChamberMeshReuse
./Scripts/Measure-VulkanPackage.ps1 -PackageRoot $package -TraceTravel -WeightVisits 8
./Scripts/Test-PackagedDisplaySettings.ps1 -PackageRoot $package
```
