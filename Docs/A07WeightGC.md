# A‑07. Полная сборка мусора при повторном входе в Weight

При переходе между камерами Unreal повторно рисовал уходящий мир после `BeginTearingDown`. Игрок этот кадр не видел. Работа рендера совпадала с ожиданием готовности удаляемых объектов в `ConditionalFinishDestroyDeferred`. После устранения лишней отрисовки p95 полной сборки мусора изменился с **12,655 до 7,734 мс**, p95 кадра перехода — с **23,799 до 20,347 мс**.

В [предыдущей серии](A07ChamberMeshes.md) значение 13,083 мс соответствовало B2, посещение 4. В сохранённом CSV для него есть время полного GC. Для разбивки по внутренним фазам потребовался новый захват той же сцены на той же машине.

## Состав паузы на игровом потоке

В новой контрольной серии p95 полного GC пришёлся на A3, посещение 2. В одном этом переходе из 12,655 мс на финальный purge ушло 7,864 мс, включая 7,080 мс отложенного FinishDestroy. Финальный FMemory::Trim занял 2,439 мс, анализ достижимости — 0,222 мс. В исправленном пакете в наблюдении на том же процентильном ранге (B3, посещение 2) отложенное завершение заняло 2,148 мс.

Строки вложены. Три фазы FinishDestroy и удаления входят в purge. У каждого процентиля свой порядок наблюдений. Для разбора конкретного пика выше взяты фазы одного посещения.

В UE 5.7.4 вызов `UEngine::LoadMapRedrawViewports` передаёт `false` в `RedrawViewports`: сцена отправляется на рендер без показа. Между камерами учебного маршрута адаптер теперь передаёт в `OpenLevel` штатную опцию `quiet`. Когда маршрут ведёт в переход к станции, сохраняется обычное поведение. У примитивов освобождение по-прежнему ждёт `DetachFence`. Проверки готовности и полный GC выполняются в обоих режимах.

Внутри `LoadMap_UnloadWorld` в A записаны один `FViewport_Draw` и один вложенный `BeginRenderingViewFamily` на каждый переход. В B оба события исчезли из выгрузки. Первая отрисовка после инициализации акторов новой камеры отправляла сцену в обоих режимах. При наблюдении на ранге p95 в A 5,008 мс из 7,080 мс отложенного FinishDestroy совпали по времени с работой рендер-потока в FDeferredShadingSceneRenderer_Render, FRDGBuilder::Execute или RenderViewFamily. В B на ранге p95 пересечение составило 1,012 из 2,148 мс. Для пересечения взято объединение интервалов. Это CPU-трасса рендера. Интервал отложенного FinishDestroy измерен на игровом потоке и включает опрос объектов. [Все посещения и фазы](Measurements/A07-WeightGCPhases.csv)

## Кадры и память процесса

Худший единичный кадр в B оказался длиннее контрольного максимума. На восьмом входе B3 кадр занял 29,092 мс, при этом GC занял 7,388 мс, LoadMap — 16,761 мс. В том же тике уже после LoadMap внутри UWorld_Tick → TickCompletionEvents игровой поток провёл 10,768 мс в WaitForTasks. Имя ожидаемой задачи эта трасса не устанавливает.

## Воспроизведение

UE 5.7.4 Win64 Development, Windows 11 build 26300, Core i5-14400F, RTX 4070 Ti SUPER, драйвер 621.24, 32 ГБ ОЗУ. План питания Windows «Высокая производительность». Vulkan SM6, Binned2, 1920 × 1080, 100%, тени 2. На время замеров отключены VSync и ограничитель FPS. Резерв MemStack выключен. В обеих сериях использованы те же модели ФосТех и их повторное использование между камерами.

SHA-256 игрового EXE `e722a7856208e0225f0fa5a9058969f3510e6f9ad6b272f8574fb39de6a44de7`, игрового контейнера UCAS `a8b045623e835b3eae491b2b1b30e51c14c48b24141cea01a6b0c8c16e0094b9`. Один пакет, шесть процессов в порядке A1, B1, B2, A2, B3, A3. По восемь входов в Weight с возвратом через Stairs, новый профиль на процесс. Первое посещение исключено из процентилей. P95 — 20-е из 21 повторного входа на режим. Кэш ОС между процессами сохранялся.

```powershell
./Scripts/Measure-VulkanPackage.ps1 -PackageRoot $package -TraceTravel -WeightVisits 8 -RedrawOutgoingChamber
./Scripts/Measure-VulkanPackage.ps1 -PackageRoot $package -TraceTravel -WeightVisits 8
```

В Timing Insights экспортируйте события игрового потока вместе с колонками ThreadName, TimerName, StartTime, EndTime, Depth. К [таймерам разбора GC](A07TravelGC.md) добавьте FViewport_Draw, BeginRenderingViewFamily, GC.VerifyAssumptions, GatherUnreachableObjects, UnhashUnreachableObjects, ConditionalBeginDestroy, ShrinkUObjectHashTables, FMemory::Trim и FTaskGraphInterface_BroadcastSlow. Проверьте как интервал выгрузки, так и отправку первого вида новой камеры.

```powershell
python Scripts/Summarize-TravelGC.py "$run/Game.log" $events --memory-tail --outgoing-redraw quiet
# Для контрольной трассы используйте --outgoing-redraw redraw.
```

## Проверка кампании

В EntryCourseAlternate камера Weight показала оба размера кубов, плиту, дверь и HUD с целью 20 кг. В журнале кампании опция quiet присутствовала на входах в Button, Weight и Balance. При старте с контрольной точки Weight она присутствовала только на переходе в Balance. Обе проверки прошли вместе с WorldLifetime, VulkanExitControl и VulkanTravelControl. [Кадр Weight после перехода, Vulkan SM6, 1920 × 1080, RTX 4070 Ti SUPER](Images/A07-WeightAfterTravel-Vulkan.png)

A‑07 остаётся открытым. P95 кадра перехода выше 16,67 мс. Следующий предмет разбора — завершение задач первого тика после LoadMap. Замеры на машине с 8 ГБ ОЗУ и целевых GPU остаются открытыми.
