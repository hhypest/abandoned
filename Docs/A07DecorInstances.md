# A‑07. Инстансинг неподвижного декора Stairs и Weight

В упакованной игре на Vulkan инстансинг сократил p95 кадра перехода Stairs → Weight с **18,621 до 16,805 мс** (−1,816 мс, или 9,8%). Доля входов в пределах 16,67 мс выросла с **4/60 до 56/60**. На этом стенде вариант B принят по умолчанию. A‑07 остаётся открытым, поскольку p95 превышает бюджет на 0,135 мс. Проверка на 8 ГБ ОЗУ запланирована после перехода проекта в статус беты.

## Что сравнивали

В одном пакете A создаёт отдельный актор и два компонента для каждого декоративного блока. Вариант B собирает трансформы блоков `Room` с `bCollision=False` и регистрирует по одному `UInstancedStaticMeshComponent` на материал, с одним владельцем на мир. Меш у всех этих блоков — стандартный куб. В Stairs 59 таких блоков, в Weight 67. В каждом из двух миров получилось по четыре группы. Они создаются заново при входе и освобождаются при выгрузке. Материал `M_AbandonedSurface` включает вариант шейдера для instanced static meshes при упаковке. При смене материала этих блоков его родительскому материалу также нужен флаг Used with Instanced Static Meshes.

Дверь, плиты, физические кубы, терминал, изменяемые сигналы и блоки с коллизией используют прежнюю сборку. Вложенные таймеры разделяют сбор трансформов и создание, заполнение и регистрацию групп. `TotalDecorMs` суммирует оба этапа. [Предыдущий замер и согласованный эксперимент](A07WeightBudget.md)

При создании входящей камеры медиана сборки декора сократилась на 1,538 мс, медиана всей инициализации акторов — на 1,584 мс. На каждом повторе GC удалял 397 объектов в A и 225 в B. Разница в 172 объекта соответствует замене 59 комплектов из актора и двух компонентов в Stairs на одного владельца и четыре компонента. При этом p95 полного GC вырос на 0,161 мс. Сильнее всего среди приведённых вложенных фаз вырос p95 обхода достижимых объектов. Ускорения полного GC серия не показала.

В B остались четыре кадра за бюджетом. В трёх из них инициализация акторов заняла 3,248–3,342 мс при медиане B 2,121 мс. В четвёртом (B3, посещение 8) первый тик мира занял 1,612 мс, полный GC — 7,672 мс. Следующий предмет A‑07 — затраты вне уже сгруппированного декора при медленной инициализации акторов и ожидание задач на первом тике. В стабильном окне (кадры 120–419 после команды перехода) p95 по визитам от покадрового p95 CPU составил 2,944 → 3,111 мс, GPU — 5,029 → 5,046 мс.

## Проверка в игре

Оба режима прошли альтернативное прохождение входного контура в пакете на Vulkan, включая сборку 20 кг из 10 + 5 + 5 кг. С режимом B дополнительно прошли восстановление из Weight, WorldLifetime, выход и контрольный цикл перезагрузок Vulkan. Журналы восьми процессов прошли проверку завершения и не содержат предупреждений о пропущенном шейдере материала.

На парных игровых кадрах сохранились контуры ниш, разметка пола, световые полосы, плита и силуэты кубов. Слева A, справа B. Сверху Stairs, снизу Weight. Для несжатых кадров 1920 × 1080 SSIM составил 0,993656 и 0,994223 соответственно. [Сравнение кадров из пакета](Images/A07-Decor-Stairs-Weight.jpg)

## Воспроизведение

Windows 11, Core i5-14400F, RTX 4070 Ti SUPER, 32 ГБ ОЗУ. Win64 Development UE 5.7.4, Vulkan SM6, 1920 × 1080, масштаб 100%, тени 2, Binned2. Во время измерения отключены VSync и ограничитель кадров. Резерв MemStack выключен. SHA-256 EXE — `eacd568fd7c75e6ff5090a411955b4bc12df1fc80c07a06007927d4b078f68d3`, игрового UCAS — `af287666a0da753807b7f8d5fccec05cd757b0dbac9993ab7df9f8bc91b90f61`.

Восемь отдельных процессов запускались последовательно в порядке A1, B1, B2, A2, B3, A3, A4, B4. Каждый начинался с чистого профиля игрока, кэш ОС сохранялся. В каждом процессе 16 входов Stairs → Weight. Первый исключён из времени повторов и включён в пик памяти процесса. Выборка для каждого варианта — 4 × 15 повторов. P95 — 57-е значение по возрастанию. Состояние декора проверяется по журналу каждого входа в обе камеры.

```powershell
./Scripts/Measure-VulkanPackage.ps1 -PackageRoot $package -TraceTravel -WeightVisits 16 -ChamberDecor Separate
./Scripts/Measure-VulkanPackage.ps1 -PackageRoot $package -TraceTravel -WeightVisits 16 -ChamberDecor Instanced
```

В Timing Insights экспортировать события GameThread с колонками ThreadName, TimerName, StartTime, EndTime, Depth, включая короткие события построения декора. Из каталога отдельного прогона и его экспорта получить фазы и показатели памяти.

```powershell
python Scripts/Summarize-WeightBudget.py $run $events
python Scripts/Summarize-VulkanProfile.py $run
```
