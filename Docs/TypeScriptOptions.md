# TypeScript в Abandoned

Предложение для решения владельца. На 22 ноября 2026 г. игровой модуль, правила головоломок и сохранения реализованы на C++20. Для «Бортового стенда» утверждён перенос HTML-эталона в UMG/Slate. Эти два решения можно оценивать независимо. [Решение по меню](MainMenuOptions.md) · [Архитектура](../Architecture.md)

| Область | Что появится | Предварительная трудоёмкость |
| --- | --- | --- |
| Инструменты авторов | Проверка ID записей Илира, ссылок терминалов и схем камер до cook. Генерация привычных игре данных. Компилятор и Node.js нужны только на рабочей машине и в CI | 2–5 человеко-дней на одну схему, команду проверки и интеграцию в CI |
| Событийный слой внутри игры | Один обработчик реагирует на выдачу записи, разрешает следующую реплику или меняет состояние самодиагностики. Ориентир 2–4 человеко-недели суммарно до первой поддерживаемой подсистемы, включая упаковку, тесты и диагностику |
| Перенос действующих игровых систем | Единый язык для авторов сложных правил потребует новых привязок к UE, переноса контрактов и повторной приёмки всех маршрутов | Порядок нескольких человеко-месяцев; оценку по подсистемам можно дать после эксперимента и инвентаризации зависимостей |

Оценки относятся к одному разработчику со знанием UE/C++, TypeScript и существующих проверок. Это инженерные диапазоны. Смена версии движка, поддержка пользовательских модов и создание полноценного редактора сценариев требуют отдельной сметы.

**Как это встраивается.** Для варианта в игре кандидат — PuerTS. TypeScript компилируется в JavaScript на этапе сборки. Плагин открывает отражённый API Unreal, чистые C++-типы требуют явных привязок. Для первой пробы я выбрал бы V8 с отладчиком. QuickJS имеет меньший размер, авторы указывают ограничения отладки. Node.js имеет смысл при конкретной потребности в его API. Совместимость выбранной версии плагина и бэкенда с собственной сборкой UE 5.7.4 предстоит проверить в Development и Shipping. [Руководство PuerTS для UE](https://puerts.github.io/en/docs/puerts/unreal/manual/) · [Сравнение бэкендов](https://github.com/Tencent/puerts#select-script-backend)

**Плюсы.** Автор может менять последовательность подсказок и реплик без пересборки нативного модуля. Типы связывают устойчивые ID, условия и команды, а чистую событийную логику можно прогонять обычными тестами до запуска Unreal. Один набор сценариев может управлять записью архива, звуком и индикацией терминала.

**Цена.** Появятся второй сборочный конвейер, версия JS-движка, его память и собственный жизненный цикл. Полезные для проекта интерфейсы придётся описать и поддерживать. При выгрузке камеры необходимо снимать подписки и таймеры, иначе поздний вызов может обратиться к ушедшему актору. Частые переходы C++ ↔ JS в каждом физическом кадре требуют отдельного измерения. Статические типы TS исчезают при компиляции, поэтому проверка входных данных и версии сохранения остаётся обязательной.

**Граница первой пробы.** Один терминал получает событие восстановления кислорода и показывает запись из архива по устойчивому ID. C++ владеет источником события, записью Save v2 и жизненным циклом мира. Физика Chaos, захват предметов, шлюз и публикация контрольной точки остаются в нативном контуре. Сравнить с текущим C++-вариантом время правки до запуска, размер пакета, холодный старт, p95/p99 кадра, пиковую RAM и освобождение подписок после повторных входов. Для проекта разумно начать с инструментов авторов; пилот внутри игры оправдан, если авторы регулярно меняют последовательности событий.
