# Устранение замечаний архитектурного аудита

Идентификаторы соответствуют независимому аудиту от 17 ноября 2026 г.

| Замечание | Выполнено | Следующий проверяемый результат |
| --- | --- | --- |
| A‑01. Автоматические проверки | CI C++20 и Git LFS, активная защита `main`, обязательный статус GitHub Actions. | Изолированная воспроизводимая UE-сборка для доверенных ревизий. |
| A‑02. Прогресс и загрузка | Описан фактический `OpenLevel`. Save v2 мигрирует четыре точки v1, сохраняет архив кампании и защищает предыдущий снимок при отказе записи. | Упакованная сборка и отдельный пилот потоковой загрузки после замеров переходов. |
| A‑03. Ответственность GameMode | Функциональные проверки учебных камер принадлежат компонентам мира. В сквозном маршруте камеры 01–03 обслуживает `UEntryChamberVerification`, камеру 04 — `UPlateBalanceVerification`. Компонент камер 02–03 проверяет также перенос и потерю DEV‑20. | Выделить проверку DEV‑20 на портальном стенде из `APortalLabGameMode`, сохранив перенос через портал и возврат узла после потери. |
| A‑04. Регрессионный контур | Именованные автономные тесты активны с `NDEBUG` и без него. Оба варианта проверяют собственный путь ошибки. UE-запускатель проверяет журнал, маркеры успеха и отрицательный контроль. | Перенос остальных функциональных сценариев на явный жизненный цикл и запуск в доверенном UE-окружении. |
| A‑05. Восстановление сессии | Правила скафандра находятся в `Application/SuitSession`, приоритет возврата — в `Application/EntryCourse`. | Развитие контракта по мере появления новых точек кампании. |
| A‑06. Наследование персонажа камеры | Учебная камера и три стенда используют `APuzzleCharacter` с компонентами захвата и постановки. Режим мира принимает команды через `IPuzzleDeviceCommands`. Все три персонажа стендов независимы от класса учебной камеры. | При изменении общего ввода повторять сценарии постановки, терминала, плит и устройств каждого стенда по [протоколу](Testing.md). |
| A‑07. Загрузка и паузы | Зафиксирована рекомендованная конфигурация и профиль Vulkan SM6. | Локализовать предупреждения об оставшихся буферах при завершении UE; замерить CPU/GPU, RAM/VRAM и холодные переходы в упакованной игре. |
| A‑08. Меню разработки | Тестовое меню продолжает открывать стенды. | Отдельный контракт пользовательского меню и состав команд Shipping. |
| A‑09. Строковые переходы | `WorldDestination`, общий кодек URL и один вызов `OpenLevel` во внешнем адаптере. | Сохранять ID и round-trip тесты при добавлении сегментов. |
| A‑10. Форма переносимого тела портала | Портал измеряет капсулу и бокс в осях проёма. Для другой формы он сбрасывает наблюдение за пересечением и выдаёт предупреждение до изменения тела. | При добавлении формы расширить адаптер и проверку геометрии в сценарии `Portals`. |
| A‑11. Решения и сопровождение | Есть контракты прогресса и графического профиля, протоколы сценариев. | Фиксировать решения о переноске, streaming и упаковке по результатам их реализации. |

Проверка зажима создаётся только по `-VerifyDoorClamp` в сборке с dev automation. Компонент принадлежит миру камеры и обращается к публичным наблюдениям игровых объектов. Захват и сброс подаются клавишами **E** и **R** через Enhanced Input. [Сценарий](../Source/Abandoned/Private/Verification/DoorClampVerification.cpp)

На Windows с Vulkan SM6 выполнены полный набор из пяти сценариев на 1080p/High с шагом 1/60 с, а также зажим и порталы на 720p с шагом 1/120 с. Восстановлена привязка render target портала; проверка итогового кадра обнаруживает прежнюю заглушку. [Протокол и оставшиеся ограничения](RenderingVerification.md)
